# Double Double Bot

NBA double-double prop research, backtest and paper-trade pipeline. Vault master note: `Obsidian Vault/Double Double Bot/Double Double Bot.md` (start there); the daily procedure is the vault job `Jobs/Run Daily DD Picks`. Started 2026-10-29.

## Layout
- `tools/pull_hoopr.py` downloads ESPN box scores, team box scores and schedules (sportsdataverse hoopR-nba-data) into `data/raw/hoopr/`. Season key is the season end year.
- `tools/check_sources.py` checks which public data sources respond.
- `tools/odds_snapshot.py` logs The Odds API `player_double_double` prices (FanDuel, DraftKings, the two-way books and the other DC books; ten keys bill as one region) to `data/odds/dd_prices.csv` (column `snapshot_kind`: open or pretip) and `data/odds/snapshots/`, and every run's credits to `data/odds/credits_log.csv`. One credit per game per call. Importable (`snapshot(...)`) by the pipeline scripts.
- `tools/market_check.py` compares the latest logged prices with realized double-double rates.
- `tools/stat_structure_check.py` measures within-player stat correlations, dispersion and the arena assist effect from the game logs.
- `tools/build_dataset.py` builds `data/features/dataset_v1.parquet` (point-in-time features, spec in `docs/SPEC_v1.md`, catalog in `docs/FEATURES_v1.md`; since 2026-10-30 the build also carries five `gs_` game-state features, expected margin with home court, its size, expected total, expected pace as team x opponent / league possessions from earlier dates, pace gap, which the production model does not use, see `train_production.py`). `build_table(pb, tb, info)` is the shared feature code path that the production trainer and the daily run reuse.
- `tools/train_eval.py` runs the v1 walk-forward backtest to `data/eval/v1/`.
- `tools/train_eval_v2.py` runs the v2 models (minutes model, simulation probability, stack, blends, calibration study) to `data/eval/v2/`, spec in `docs/SPEC_v2.md`.
- `tools/edge_bands.py` assumption-based edge view by price band from the v2 predictions.
- `tools/pull_tracking.py`, `tools/pull_matchups.py`, `tools/build_tracking.py`, `tools/build_opponent_features.py`, `tools/tracking_lift.py`: the stats.nba.com tracking and matchup layer and its controlled lift test (`data/eval/tracking/report_tracking.md`). Result 2026-10-29: no measurable lift. 2026-10-30: with box-out success ratios added (own rebound, team rebound and defensive share per box out; `data/eval/tracking_boxout/report_tracking.md`, the prior report kept beside it) the residual tracking layer clears its pooled interval against the production model by 0.00025 of log loss in raw form and is flat after calibration; `tracking_lift.py --extra` tests one more feature group alongside. The layer is not part of the production model and the daily pipeline does not call stats.nba.com.
- `research_notes/` five cited research notes; `reports/NBA double double prop models.md` the synthesis.

## Paper-trade pipeline (built 2026-10-29)
- `tools/paper_common.py` shared pieces: ESPN scoreboard, injuries, rosters and box scores (public JSON), de-vig (multiplicative and power), the price board, name matching, file paths, the voice check on generated text.
- `tools/train_production.py` fits the production model (v1 C_full on the 155 v1 features, Platt-calibrated on the last 15 percent of rows by date) on every season through yesterday, rebuilding the feature table into `data/features/dataset_prod.parquet` through `build_table`. `--feature-set gs` trains on the 160 with the game-state features; every run also fits the other set on the same rows, holdout and seed and records it in the manifest, the before-swap check. 2026-10-30: the game-state set did not reproduce its controlled-test gain in production form (holdout Platt log loss within 0.00006 of the v1 set across two fits, which is also how far the same 160-feature fit moved between runs; four-season test -0.00006 with the interval crossing zero), so production stays on the 155 (`data/eval/gamestate_prod/`, `data/eval/gamestate_prod6/`). Outputs `data/models/production/` (booster, `platt.json`, `manifest.json`, `features.json`, `training_history.csv`). The daily run retrains when the manifest is older than 7 days.
- `tools/daily_run.py` the morning run: hoopR refresh, slate and injuries and rosters from ESPN, pending rows for every available rostered player appended to the history and featured through `build_table`, calibrated probabilities, price snapshot, fair probabilities from the two-way quotes, edge selection (thresholds at the top of the file), `data/paper/picks_{date}.csv`, `board_{date}.csv`, `discord_{date}.md` (text in the strikeout bot's layout; nothing is posted). `--reuse-prices` replays the logged snapshot at no cost; `--date` with a past date backfills a day from its actual lineups; `--no-odds` skips prices; `--dry-run` builds and predicts only (no prices, files or run-log row), the check of the live path after a model change.
- `tools/pretip_snapshot.py` before tip: prices for the picked games only, injury re-check (ruled out becomes void), closing FanDuel, best and fair prices written into the picks file, `discord_pretip_{date}.md`.
- `tools/grade.py` next morning: grades yesterday from the box scores (hoopR, else the ESPN summary), pays the paper stake at the open and close, computes fair closing line value under both de-vig methods, replaces the date's rows in `data/paper/ledger.csv`, writes `discord_grade_{date}.md` with the day's record and the season line against the 100-pick gate. A date with no picks file (no run that day) grades as nothing to grade, so a skipped day does not stop the chain (fix of 2026-11-01).
- `tools/top_post.py` the daily post Russ asked for on 2026-10-29 ("I just want 5 dudes sent to phone like strikeout"): the five most likely double-doubles on the board ranked by calibrated model probability, players listed out or doubtful dropped, players on the second night of a back-to-back dropped (Russ, 2026-11-04: "no back to backs with players"; the model's `team_b2b` and `b2b` flags, switch `EXCLUDE_B2B` in `paper_common.py`, also applied to the edge-rule picks), one line each with team, opponent, tip time, model percent and the FanDuel price, a green mark when the model sits above FanDuel's implied probability, the edge-rule value play when there is one, and last night's result plus the season record of these posts from `data/paper/ledger_top.csv`. Writes `data/paper/discord_top_{date}.md` and `top_{date}.csv`; `grade.py` grades the five at the FanDuel price. The edge-rule picks, board and price log keep running underneath for the 100-pick closing-line gate.
- `tools/pair_correlation.py` (2026-10-30) how double-double outcomes move together inside a game, for combo pricing: on the v1 test seasons two legs in one game hit together about 0.93 times the product of their probabilities (same team 0.92, opponents 0.95); a starter with his own team's bench 0.55, two same-team centers 0.69, center plus guard 1.05; games decided by under 10 points 1.05 to 1.17, by 20 or more about 0.5. Report in `data/eval/pairs/report_pairs.md`.
- `tools/build_gamestate_features.py` (2026-10-30) point-in-time game-state proxies from the box scores (expected margin from trailing point differentials plus home court, its absolute value, expected total, team x opponent / league pace, pace gap, opponent differential) and foul-trouble and minutes-volatility features; also the residual-by-expected-margin table. Tested with `coach_lift.py`: game-state features improve pooled calibrated log loss by 0.00022 (bootstrap interval -0.00045 to -0.00001, the first feature group to clear its interval, about 2 percent of the model's advantage over the season rate) with a proxy that correlates only 0.14 with the final margin; foul features -0.00015, interval crossing zero. Reports in `data/eval/gamestate/` and `data/eval/fouls/`. Re-tested the same evening in production form after Russ's go-ahead (`build_table` computes them; correlations with the prototype 0.998 to 0.9999): -0.00006 pooled with the interval crossing zero, the six-feature replication with the duplicated opponent differential -0.00017 (interval -0.00041 to +0.00003); three near-identical runs therefore give -0.00022, -0.00006 and -0.00017 against intervals about 0.0002 wide, an effect the size of its own noise; not adopted, the morning result was noise at the edge of its interval.
- `tools/pull_shot_quality.py`, `tools/build_shot_features.py` (2026-10-30, Russ: "open 3s taken (for assist)") per-game attempts by closest-defender band (4-6 feet open, 6+ feet wide open) from stats.nba.com for 2023-24 onward, one request per band and game date with the same block-aware retry loop as the tracking pull, and 11 point-in-time features from them: the player's open threes per minute, open share and open make rate, his teammates' open threes per game, the opponent's open threes allowed. Tested in both harnesses (`data/eval/shots/report_shots.md`, `data/eval/shots_era/report_tracking.md`): no lift (+0.00007 and +0.00006 against BASE, -0.00000 as a residual layer on the production model); potential assists already carry the information. Not adopted.
- `research_notes/NBA double double prop models/stokastic_nba_dfs.md` (2026-10-30) the 22 Stokastic NBA DFS articles read at Russ's request, what transfers, the tests run and the backlog; per-article notes in the `stokastic nba dfs 2026-10-30/` folder.
- `tools/post_discord.py` posts a day's summary as the Discord embed the strikeout bot uses; the default kind `top` sends the five-name post whole, `picks` sends the headline of the edge-rule summary (everything above the footer lines); dry run by default, `--post` sends to `DISCORD_WEBHOOK_URL` (environment, this project's `.env`, or the StrikeOut Bot `.env`, never printed), `--ny-hour` is the schedule guard, `--label` tags a test post, `--once` skips the send when the run log already holds the day's post (the Action's daily step uses it).
- `tools/fallback_post.py` (2026-11-01, Russ: "Yes. Schedule a one-shot fallback ... that runs grade, daily run, top post and the Discord post only if the run log has no post for today yet.") the 3 PM chain by hand when the Action has not posted: pulls, then every 4 minutes reads the run log and the public GitHub API for the day's Action runs; stops when a post exists, waits while a run is in progress, and runs grade, daily run, top post and the `--once` post by hand when a run failed before its post step or none exists by 3:40 PM Eastern, then commits the outputs back as the Action does. Run from a session cron or by hand; `--check` prints the decision only.
- `tools/ci_gate.py` (2026-11-08, replaces `ny_hour_guard.py`) decides which step a scheduled Action run performs, from the New York clock and from the checkout's run log, with the standard library only: `daily` (14:50 to 19:00 ET, nothing posted yet), `post` (the daily run is done, the send is retried), `pretip` (18:30 to 19:30 ET, a pick without a closing snapshot), `none` (also a day with no games). `--now "YYYY-MM-DD HH:MM"` simulates the clock for a local test.
- `.github/workflows/daily_dd_discord.yml` the GitHub Action, which runs without the Claude app or this computer. Ten crons off the hour mark (18:53, 19:23, 19:53, 20:23, 20:53 and 21:23 UTC for the daily window, 22:41, 23:11, 23:41 and 00:11 UTC for the pre-tip window; 3 PM Eastern is 20:00 UTC in standard time and 19:00 UTC in daylight time) because GitHub started the on-the-hour crons 5 to 9 hours late and the earlier exact-hour guard then skipped every run (found 2026-11-08; Russ: "this shouldnt rely on claude coder being open to run it should run everyday like how the strikeout did"). Each run starts with the gate, so the first run inside a window does the step and later runs stop in seconds. `workflow_dispatch` takes a step input (`post_test` runs the chain and sends one labeled test post), the install uses `requirements-ci.txt`, the secrets are `ODDS_API_KEY` and `DISCORD_WEBHOOK_URL`, and `data/paper`, `data/odds` and `data/models/production` are committed back.
- `data/paper/run_log.csv` one line per run; `data/paper/logs/` the console output of every run.

## Running
All scripts run from the project root with `PYTHONUTF8=1 python tools/<script>.py`. Python 3.13 with pandas, numpy, scipy, lightgbm, scikit-learn, pyarrow, requests, plus `nba_api` 1.12 (installed 2026-10-29 with Russ's go-ahead) for the tracking and matchup pulls only. `.env` (optional) holds `ODDS_API_KEY`; otherwise the StrikeOut Bot `.env` is read. Paper stakes only; no scheduled task exists.
